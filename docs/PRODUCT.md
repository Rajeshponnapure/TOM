# Product

## Register

product

## Users

Rajesh Ponnapureddy — single owner-user. Uses TOM daily for personal laptop automation in a
bright office or well-lit room. Mouse and keyboard. Expects a tool that feels like a capable,
present companion, not a generic utility. The primary job: delegate tasks (open apps, manage email,
browse, write code, run automations) to TOM without friction.

## Product Purpose

TOM is a local Windows desktop AI agent for personal laptop automation. It connects Ollama LLM
with Playwright, Gmail OAuth, screen tools, voice I/O, and a scheduler to let one person control
their entire laptop through natural language. Success looks like: Rajesh says something, TOM does
it, and the interaction feels effortless and reliable. Not a chatbot. Not a dashboard. A capable
entity you give work to.

## Brand Personality

Intelligent, bold, alive. TOM is not a SaaS product with a logo. It is a presence. The UI should
feel like opening a conversation with something that knows what it is doing and is ready before you
even type. Warm enough to feel personal, sharp enough to feel expert, animated enough to feel alive.

## Anti-references

- Generic SaaS dashboards: Notion clones, hero metrics, pastel card grids, open container stacks
- Corporate enterprise tools: gray tables, checkbox forests, zero personality
- Sci-fi "hacker" aesthetic: matrix rain, terminal green on black, glitch overuse
- Consumer chatbot UIs: rounded bubble chat, emoji-heavy, ChatGPT/Copilot lookalike energy
- Any UI that looks like it was designed for a product category rather than for TOM specifically

## Design Principles

1. **Presence before utility.** The animation and character are the product, not decoration. TOM
   must feel alive in the first two seconds before the user types a single word.
2. **One surface, full focus.** No open container dashboards, no visible checkbox lists, no panel
   stacking. The active view is the only view. Everything else recedes.
3. **Contrast as confidence.** Designed for bright ambient light. High contrast is not a fallback;
   it is how the design holds authority in the room.
4. **Intelligence made visible.** Every state change — loading, thinking, responding, error —
   communicates TOM's awareness. Nothing is silent. Nothing is generic.
5. **Personal, not categorical.** TOM has a specific character. The UI must feel like interacting
   with this entity, not a design system that could belong to any AI tool.

## Accessibility & Inclusion

WCAG AA minimum. High contrast ratios required (bright room use). Text sizes must be comfortable
at arm's length from a desktop monitor. Reduced motion: animations should have a fallback path.
No color-only signaling — state must be readable by label or shape, not just hue.
